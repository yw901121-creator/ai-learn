# 第 3 章｜什麼是 AI Agent？

## 一句話重點

**Chatbot 會聊天；Agent 會做事。**  
Agent = LLM + 目標 + 規劃 + 工具 +（常有）記憶。

---

## 1. Chatbot vs Agent

| | Chatbot | Agent |
|---|---|---|
| 輸入 | 一句話 | 一個目標 |
| 輸出 | 一段文字 | 一連串動作與結果 |
| 例子 | 「解釋光合作用」 | 「幫學生生成本週練習卷並通知老師審核」 |
| 風險 | 講錯 | 做錯（影響系統資料） |

---

## 2. Agent 四大零件

```
┌─────────────────────────────────────┐
│              AI Agent               │
│  1. 大腦 LLM（理解與規劃）            │
│  2. 工具 Tools（搜尋、DB、API、瀏覽）  │
│  3. 記憶 Memory（短期對話 / 長期檔案） │
│  4. 目標 Goal（完成任務的成功條件）    │
└─────────────────────────────────────┘
```

### 典型工作循環（ReAct 思路）
```
思考 → 選工具 → 執行動作 → 觀察結果 → 再思考 → … → 完成
```

---

## 3. 2026 熱詞：Agentic AI

意思是系統具備：

- **自主規劃**（拆任務）
- **工具使用**（真的去執行）
- **多步堅持**（long-horizon）
- **在規範內行動**（權限、審批）

產品例子：

- Cursor Cloud Agent：改 code、跑測試、開 PR  
- 教育場景：學習預警 Agent、自動組卷 Agent、課程助教 Agent  

---

## 4. Multi-Agent（多代理人）

一個複雜任務拆成多個專責 Agent：

| Agent | 職責（教育例子） |
|---|---|
| Tutor Agent | 答疑、引導 |
| Assessor Agent | 出題、評分 |
| Analyst Agent | 學習數據預警 |
| Guardrail Agent | 檢查是否洩題、是否偏見 |

好處：模組化、可審計  
代價：協調成本、錯誤可能互相放大

OpenAI GPT-5.6 的 **`ultra`** 模式，概念上就是多 Agent 平行協作加速難題。

---

## 5. Computer Use（電腦操作）

AI 能看螢幕、點擊、填表、操作 GUI。  
2026 旗艦模型強調這能力 → 更接近「數位員工」。

教育用途想像：

- 自動在 LMS 後台建立課程單元  
- 批次匯入題庫  
- 協助老師操作複雜後台  

風險：權限過大、誤操作 → 需要人工確認關卡。

---

## 6. 教育 Agent 設計原則

1. **預設只讀**，寫入要審批  
2. **對學生引導，不洩完整答案**（考試模式例外規則）  
3. **每個動作可記錄**（audit log）  
4. **失敗要可回滾**  
5. **老師永遠是最終權威**

---

## 面試金句

> 「Agent 讓 AI 從『回答問題』升級成『完成工作流』。  
> 在教育產品裡，我最在意的是權限、可審計、以及教學倫理——能做事，但不能亂做事。」

---

## 小測驗

1. Agent 比 Chatbot 多了什麼？  
2. Multi-Agent 的優缺點？  
3. 教育 Agent 為什麼不能給寫入權限太大？

<details>
<summary>參考答案</summary>

1. 目標、規劃、工具執行、（常有）記憶  
2. 優：分工專業；缺：協調難、錯誤放大  
3. 誤改成績、誤發通知、資料損壞；需審批與日誌  

</details>
