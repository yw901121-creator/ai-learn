# 第 2 章｜Prompt、RAG、Fine-tuning（三件套）

## 一句話重點

讓 AI 變強有三條路：**寫好指令（Prompt）→ 接上資料（RAG）→ 專精訓練（Fine-tune）**。  
教育產品 **90% 先做 Prompt + RAG**，Fine-tune 是進階選項。

---

## 1. Prompt Engineering（提示工程）

### 是什麼？
設計給模型的指令與範例，讓輸出更穩、更符合需求。

### 常用技巧
| 技巧 | 說明 | 教育例子 |
|---|---|---|
| Role | 指定角色 | 「你是高中數學助教」 |
| Constraints | 設限制 | 「不要直接給最終答案」 |
| Few-shot | 給範例 | 給 2 題「好的引導式回覆」當樣本 |
| Structured output | 要求格式 | JSON：題目、難度、知識點、解析 |
| Chain-of-Thought | 要求分步 | 「一步一步推理，但對學生只顯示引導」 |

### 教育產品必加的 Prompt 規則
1. 不確定就說不確定，建議問老師  
2. 優先引用課程單元  
3. 用提問引導，不直接洩題  
4. 適齡用語（國小 vs 大學不同）

---

## 2. RAG（Retrieval-Augmented Generation）

### 是什麼？
**先檢索，再生成。**  
把教材、講義、FAQ 放進資料庫；學生提問時，先找出相關段落，再讓 LLM 依據這些段落回答。

### 為什麼教育超需要？
- 降低幻覺（教錯）
- 答案可引用來源（可解釋）
- 教材更新不必重訓模型

### 簡易流程
```
學生問題
  → Embedding（把文字變向量）
  → Vector DB 相似度搜尋
  → 取出 Top-K 教材片段
  → 連同問題送給 LLM
  → 生成「有根據」的回答
```

### 關鍵元件
| 元件 | 作用 |
|---|---|
| Embeddings | 把文字轉成語意向量 |
| Vector Database | 存向量、做相似搜尋（如 Pinecone、pgvector） |
| Chunking | 把長教材切成小段 |
| Reranker | 二次排序，提高相關性 |
| Citation | 標註引用哪一頁/哪一課 |

### 面試金句
> 「RAG 是知識來源；沒有 RAG 的教育 AI，就像老師不看書憑印象教書。」

---

## 3. Fine-tuning（微調）

### 是什麼？
用自己的資料繼續訓練模型，讓它更懂領域用語或固定風格。

### 什麼時候才需要？
| 適合 | 不適合先做 |
|---|---|
| 要固定題型/格式 | 教材常改（RAG 更合適） |
| 品牌語氣一致 | 資料少又髒 |
| 領域術語極多 | 預算/人力不足 |

### 和 RAG 怎麼選？
```
資料要「查得到最新內容」 → RAG
行為要「穩定像我們的老師」 → Fine-tune（或強 Prompt）
兩者都要 → 生產級系統常 RAG + 輕量微調
```

---

## 4. 三者對照（必背表）

| | Prompt | RAG | Fine-tune |
|---|---|---|---|
| 改動成本 | 低 | 中 | 高 |
| 更新速度 | 即時 | 快（更新索引） | 慢（重訓） |
| 防幻覺 | 有限 | 強 | 中 |
| 教育首選 | ✅ 必做 | ✅ 幾乎必做 | ⚠️ 進階 |

---

## 小測驗

1. 為什麼教育 AI 幾乎一定要 RAG？  
2. 「不要直接給答案，改用提問引導」屬於哪種手法？  
3. 教材每週更新，該 Fine-tune 還是 RAG？

<details>
<summary>參考答案</summary>

1. 降低教錯、可引用教材、更新不必重訓  
2. Prompt 約束 / 教學策略（Scaffolding）  
3. RAG（更新索引即可）  

</details>
